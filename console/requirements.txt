# Jindal Stainless surface inspection console -- runtime dependencies.
#
# PRIMARY HOST: Streamlit Community Cloud (free). Choose **Python 3.11** in the
# app's Advanced settings when you create it -- that is not the platform default,
# and it is what the `+cpu` wheel tags below are resolved against. DEPLOY.md says
# where that dropdown is.
#
# Budget on that host is of the order of 1 GB of RAM for the whole container,
# which is the tightest constraint on this file: see the MEMORY BUDGET comment in
# app.py and `tools/measure_memory.py`, which measures the app against it. It also
# still builds as a Docker image (see Dockerfile) for self-hosting, where the
# budget is whatever the host gives it.
#
# Only packages this Space's own code imports are listed, so this file is the
# dependency surface a reviewer has to trust; everything else arrives
# transitively. Versions are the ones the system was built and measured against.
#
# ---------------------------------------------------------------------------
# THE ONE LINE THAT MATTERS: torch must resolve to the CPU build.
#
# `torch==2.14.0` from PyPI carries, for `platform_system == "Linux"`, hard
# requirements on cuda-toolkit 13.0.3, cuda-bindings, nvidia-cudnn-cu13,
# nvidia-cusparselt-cu13, nvidia-nccl-cu13, nvidia-nvshmem-cu13 and triton. That
# is several gigabytes of CUDA payload on a host with no GPU, and on Spaces it is
# a build that exceeds its time and image budget rather than one that merely
# wastes space. The CPU-only wheel is a separate distribution with a `+cpu` local
# version, published on PyTorch's own index and nowhere else:
#
#     torch-2.14.0+cpu-cp311-cp311-manylinux_2_28_x86_64.whl        196 MB
#     torchvision-0.29.0+cpu-cp311-cp311-manylinux_2_28_x86_64.whl
#
# so the index below is required for the pins to resolve at all. It is an
# --extra-index-url rather than an --index-url deliberately: every other package
# here must still come from PyPI.
#
# The markers keep this file installable on macOS too -- the project's
# development host, where `pip install -r requirements.txt` is how it is verified
# before a push. PyTorch publishes no `+cpu` wheel for macOS, where the ordinary
# PyPI wheel is already accelerator-free of CUDA and carries Metal instead, so
# the plain pin is the right one off Linux.
# ---------------------------------------------------------------------------
--extra-index-url https://download.pytorch.org/whl/cpu

torch==2.14.0+cpu; sys_platform == "linux"
torchvision==0.29.0+cpu; sys_platform == "linux"
torch==2.14.0; sys_platform != "linux"
torchvision==0.29.0; sys_platform != "linux"
